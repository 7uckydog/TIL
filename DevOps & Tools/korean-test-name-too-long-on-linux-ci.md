# 윈도우에선 되는데 리눅스 CI에서만 빌드가 깨졌다 (파일명 길이 한도)

> 한글 테스트 이름이 길어서, 컴파일된 `.class` 파일명이 리눅스 파일명 한도(255바이트)를
> 넘겨 CI에서만 `File name too long`으로 터진 사건. 윈도우는 멀쩡했다.

## 증상

- 윈도우 로컬(IntelliJ): 테스트 전부 통과 ✅
- 리눅스 CI(Drone): 특정 테스트 1개에서 `File name too long`으로 실패 ❌
- 코드는 똑같은데 **환경만 다르면 결과가 갈렸다.**

## 헛다리부터 짚었다

처음엔 이렇게 의심했고 전부 틀렸다.

- ❌ 날짜가 지나서 테스트가 깨짐 (`LocalDate.now()` 의존) → 알고보니 이미 mocking 중
- ❌ `mockkStatic` 전역 오염 / 테스트 실행 순서 차이
- ❌ 내부망/외부망 네트워크 차이

결정타는 **실제 에러 메시지 한 줄**이었다 → `File name too long`.
추측으로 30분 날린 뒤에야 로그를 봤다. **추측 말고 에러부터 봤어야 했다.**

## 진짜 원인

Kotlin은 테스트 메서드 안의 람다(`every {}`, `answers {}` ...)를 이런 식의
**별도 `.class` 파일**로 컴파일한다.

\`\`\`
클래스명$메서드명$1.class
\`\`\`

긴 한글 메서드명이 파일명에 그대로 들어가는데, 그 파일명이 **271바이트**였다.

## 왜 윈도우는 OK, 리눅스만 터지나

파일명 한 칸의 한도(255)를 **세는 단위가 OS마다 다르다.**

| | 세는 단위 | 그 파일명 | 255와 비교 | 결과 |
|---|---|---|---|---|
| 윈도우 NTFS | **글자수** (UTF-16) | 187 글자 | 187 ≤ 255 | ✅ 통과 |
| 리눅스 ext4 | **바이트수** (UTF-8) | 271 바이트 | 271 > 255 | ❌ 실패 |

UTF-8에서 **한글 1글자 = 3바이트**, 영문/숫자 = 1바이트.
→ 한글이 많으면 리눅스에서 한도에 3배 빨리 닿는다.
같은 이름이 윈도우(187)에선 멀쩡, 리눅스(271)에선 사망.

> ⚠️ 255는 **"경로 전체"가 아니라 "파일/폴더 이름 한 칸"**의 한도다.
> (리눅스 전체 경로 한도는 별도로 4096바이트 = `PATH_MAX`)

## 해결

- 프로덕션 코드 0줄. **긴 테스트 메서드 이름만 단축**(271B → ~215B).
- 검증: 컴파일 후 `.class` 파일명을 전수 스캔해 255바이트 초과 0개 확인.

PowerShell로 초과 파일 찾기:

\`\`\`powershell
Get-ChildItem build\classes\kotlin\test -Recurse -Filter *.class |
  Where-Object { [Text.Encoding]::UTF8.GetByteCount($_.Name) -gt 255 } |
  ForEach-Object { "{0}B  {1}" -f [Text.Encoding]::UTF8.GetByteCount($_.Name), $_.Name }
\`\`\`

## Takeaways

1. **"로컬은 되는데 CI만 깨진다" = 환경 차이부터 의심** (OS / 파일시스템 / 인코딩 / 타임존).
2. **추측 금지, 실제 에러 메시지부터 확보.** "File name too long" 한 줄이 삽질을 끝냈다.
3. 한글 식별자(특히 긴 BDD 테스트명)는 **UTF-8 바이트 길이**를 의식하자.
   리눅스 파일명 한도는 255 **바이트**다.
